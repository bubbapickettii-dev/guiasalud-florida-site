Imported contacts — records we hold, not consent we have

Third-party records (datasets, exports, licensed sources) live in imported_contacts in the lead database, never in leads. A row here is evidence that we possess a contact — nothing more. There is no call, email, DM, export or sell action on this page. The only way a row becomes eligible is linking it to the same person's own /check submission, whose consent row already exists.

Two separate questions, two separate columns: data status = is it a real person/organisation (VERIFIED_REAL from an authoritative registry, UNVERIFIED from an unattested export, SYNTHETIC generated); eligibility = may we use it for marketing (almost never, and never automatically). A real record we may not call is the normal, expected state.

Why none of this is sellable yet: routing (engine/route.py) reads only leads, and a leads row's phone must be CONSUMER_SUBMITTED — a database trigger refuses anything else. So an imported number cannot enter a sale. The counter above is a live audit of that guarantee and must stay 0. Import an export

Paste a CSV (header row required). Any of these column names are understood: name/full_name/title, first_name, last_name, email, phone/mobile, telegram/username, city, state, zip, url/profile_url/website, date/signup_date, id. Everything else is kept verbatim on the row. Duplicates are stored as inert DUPLICATE rows — the original's phone, email, provenance and eligibility are immutable, so a re-import can never overwrite consent evidence.

No row can arrive consented; no lead or consent is ever created here.
